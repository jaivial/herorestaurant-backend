# pgnative-A — native PostgreSQL schema generator (source/build only)

Authority: Main 11:57, "PostgreSQL nativo". Nothing was run against any database. The old worktree was not touched.

## What changed (internal/dbmigrate, cmd/dbmigrate, cmd/pgnative-gate)
- **native.go (new).**
  - `AppNormSQL` is identical to docs/pgnative/app-norm.sql: the unaccent extension, schema app, app.norm and app.norm_ascii.
  - `NormFunc` picks the folding function per column.
  - `NativeUniques` lists every source UNIQUE (non-PRIMARY, BTREE) index that has at least one text/char part. Each becomes `ux__<table>__<index>`: a UNIQUE expression index with app.norm*(col) on the text parts and the non-text parts raw, in the same column order and DESC flags. NULL semantics are the PG default (NULLs distinct, as in MySQL).
- **plan.go.**
  - The plan now creates the app schema and functions first. There is no `CREATE COLLATION dbmigrate.ci_ai`.
  - Each text-unique index emits its `ux__` index instead of the raw unique. The raw UNIQUE index is kept only when an FK references that exact column set; that count is 0 on this schema.
  - Every FK DDL ends with `NOT VALID`.
  - The `__wk` exclusion loop was removed from dbmigrate.on_update_ts. ON UPDATE triggers stay, and the gate hash follows the same source.
  - The pad_space pending entries were removed, since key semantics are now decided by app.norm.
- **types.go / padmeta.go.** `_ci` collations map to the default collation (no COLLATE). `_bin` collations stay `"C"` (14 columns, deterministic).
- **pgimport.go.** FKs are created NOT VALID. Each FK with 0 orphans is then `VALIDATE CONSTRAINT`-ed in the same transaction. Orphaned FKs (allowlist, 731 rows expected) stay NOT VALID; their rows are never deleted and no parents are invented. The ready flag stays false while any NOT VALID FK exists.
- **cmd/dbmigrate.** New modes `native-inventory` and `native-convert`. Both read only schema.json; there is no DB access.
- **cmd/pgnative-gate (new).** Read-only: a single `READ ONLY` transaction that is rolled back, with the DSN taken from PG_DSN and never printed. It checks:
  1. no `__wk`/`__pad` columns
  2. no dbmigrate collation, no ixwk/ixpad index, no index expression using dbmigrate.*
  3. all 117 `ux__` indexes exist, are valid and unique, and their expressions match (normalized pg_get_indexdef)
  4. a FK report: planned vs present, the NOT VALID list, and an orphan count per NOT VALID FK using the plan's orphan-check SELECTs (731 expected; report only)
  5. the trigger count vs the plan
  6. app.norm and app.norm_ascii exist and are IMMUTABLE

## Norm rule
- **app.norm_ascii** (lower + rtrim) when either:
  - the MySQL collation is `*general_ci`, or
  - the column name is an ASCII identifier: email, slug, token, hash, guid, uuid, domain, subdomain, url, sha256, `*_id`, `id`, `*idempotency_key`, `*_key`, `k`.
- **app.norm** for every other text column: names, labels, sku, codes, ticket/full numbers, targets, phones, usernames.
- The per-index choice is in docs/pgnative/native-ddl-inventory.tsv, column norm_functions.

## Artifacts (generated from /tmp/villacarmen-bot-20261111/derived-localmeta-20261112/schema.json)
- docs/pgnative/native-ddl-inventory.tsv: 117 indexes. Columns:
  - table, MySQL index, columns, text columns, norm functions
  - pg index name, DDL
  - exact `ON CONFLICT (...)` target
  - raw-kept flag
- docs/pgnative/convert-existing-scratch.sql: idempotent conversion for an old-way scratch, generated by `dbmigrate -mode native-convert`, ending in ROLLBACK. Order:
  1. app norm
  2. save and drop the public views
  3. drop constraints on `__wk`/`__pad` (FKs first)
  4. drop ixwk/ixpad indexes
  5. drop `__wk`/`__pad` columns
  6. CREATE OR REPLACE the on_update functions
  7. drop the 117 raw `ix__` text uniques
  8. fail closed if any index expression still uses ci_ai
  9. ALTER every column with a dbmigrate collation to `COLLATE "default"`
  10. CREATE UNIQUE INDEX IF NOT EXISTS for the 117 ux indexes
  11. create the 293 FKs NOT VALID if absent
  12. recreate the views
  13. DROP COLLATION dbmigrate.ci_ai

## Not verified
- Nothing has been run against a DB: neither the convert script, nor a fresh import, nor the gate.
- ALTER COLUMN TYPE ... COLLATE "default" may fail on columns used by generated-column expressions, and dependent views must recreate cleanly from pg_get_viewdef; both need scratch QA.
- Existing scratch FKs keep their current state (validated or NOT VALID); the script only adds the missing ones.
- The gate's expression match uses a normalized string compare, not an exact one; the pg_get_indexdef rendering is unverified.
- internal/api still uses the old ON CONFLICT/ci_ai/`__wk` SQL. It will not work on the native schema until it is ported to the TSV targets (task B).
- PRIMARY KEYs with text columns stay raw (byte equality); this is not covered by app.norm.
- The norm_ascii name rule is a heuristic. Review the list, e.g. username, phone, code.
