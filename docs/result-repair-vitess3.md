## 1. internal/mysqlcoll wrapper (design)
```go
package mysqlcoll

type Coll struct{ c colldata.Collation; pad bool; name string }

// New: name and pad come from SOURCE metadata (information_schema.COLLATIONS
// PAD_ATTRIBUTE, export sidecar). Unknown collation or missing pad -> error.
func New(name string, padSpace bool) (*Coll, error)

var ErrInvalidUTF8 = errors.New("mysqlcoll: invalid utf8mb4 input")

// Key: canonical equality/unique key. PAD SPACE: naked WeightString(src,0)
// minus trailing whole SPACE-weight units (WeightString(" ")). NO PAD: naked.
func (c *Coll) Key(src []byte) ([]byte, error)

// Equal: bytes.Equal(Key(a), Key(b)). Never the library Collate (not PAD-aware).
func (c *Coll) Equal(a, b []byte) (bool, error)

// Compare: bytes.Compare of keys, for ORDER BY parity (same weight order).
func (c *Coll) Compare(a, b []byte) (int, error)

// Like: library Wildcard on ORIGINAL bytes ('_', '%', '\\'). No trimming,
// no keys. Compiles once per pattern.
func (c *Coll) Like(pattern []byte) (func(s []byte) (bool, error), error)
```

Rules:
- **Every entry point checks `utf8.Valid` and fails closed** (ErrInvalidUTF8). The library silently stops at invalid bytes; for example 0xFF produced an empty key.
- **_bin columns:** utf8mb4_bin is PAD SPACE with codepoint weights. Use the same Key rule, with collation name and pad taken from metadata.
- **Binary (non-text) columns** never use mysqlcoll.
- **Avoided:** `WeightStringLen` and `PadToMax` (PadToMax needs a preallocated dst, otherwise it silently returns empty), and `Hash` (collides).
- **Panics:** each entry point recovers a library panic and returns an error, so the caller fails the request.
- **Collation lookup:** a static name→colldata map built once at startup. A collation that is absent refuses.
- **Storage:** `<col>__wk bytea` (future, unapplied).
  - Unique: `(scope…, <col>__wk)`.
  - Lookups: `WHERE <col>__wk = $1`, with the key computed in Go.
  - Raw values stay byte-exact.
- **Key size:** must be computed per column (expansions such as ß→2 units). Refuse an index if the maximum exceeds btree limits.
- **Writers:** every writer must set `__wk` through one helper. External or raw-SQL writers cannot be covered: that gate stays and needs a readiness check comparing key vs Key(raw) (§4).

## 4. Count-only per-column key comparison tool (design, not built)
`cmd/collkey-compare`: a manual diagnostic, not a test. It lives in the review module until the dependency is approved.

Inputs and connection rules:
- Env DSNs, never printed: `CKC_MYSQL_DSN` (local villacarmen_source) and `CKC_PG_DSN` (scratch).
- MySQL connects `SET SESSION TRANSACTION READ ONLY` with START TRANSACTION READ ONLY. PG uses `default_transaction_read_only=on` and refuses unless `SHOW transaction_read_only` = on.
- Args: `-columns file`, with lines `table.column collation pad` taken from the schema sidecar.

Per column it outputs counts only, never values or keys:
- `rows` (equal count on both sides, joined by primary key);
- `invalid_utf8` (rows the wrapper refuses);
- `go_key_vs_mysql_weight` mismatches. MySQL `WEIGHT_STRING(col)` is not canonical for PAD SPACE (vitess2), so this is compared after the same trailing-SPACE-weight strip, plus a raw-weight-equal count;
- `dup_groups_go_key` vs `dup_groups_mysql_eq`: for unique-key columns, GROUP BY column on MySQL against grouping by Go key; counts must match;
- `pg_raw_bytes_match`: sha256 of raw bytes per PK, MySQL vs PG; only the mismatch count is printed;
- `max_key_len` (bytes) and `max_candidates_per_tenant` (for LIKE bounds).

Behaviour rules:
- Streaming per PK in batches, with a memory cap; refuses tables without a PK.
- Output: JSON aggregates only.
- Any mismatch count above 0 leaves that column blocked. Nothing is waived.
